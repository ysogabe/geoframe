# ライブラリの見直し（カードの横並び・選んで見る・検索・場所と地図の統合） PRD

作成日: 2026-11-02。状態: 設計レビュー 2 回（Sol）・安全面レビュー 1 回（Opus）を反映済み。2026-11-02 ユーザー承認。実装済み（tasks.md）。

## 背景と目的

管理画面のライブラリタブ（[B の PRD](../admin-library/prd.md)、PR #74・#76）は「旅・日付・場所・地図」の 4 つの眺め方を持つが、
2026-11-02 にユーザーが画面を見て「使いにくい」と判断した。原因は次の 4 つ。

- カードが 1 行に 1 枚で、幅いっぱいに伸びる。名前と枚数の間が空き、1 画面に 13 件ほどしか見えない。
- 日付・場所のカードは文字だけで、写真が 1 枚も無い。
- 「写真を見る」で一覧が格子に置き換わり、別の旅・年・県を見るたびに「◀ 戻る」を往復する。
  日付・場所のカードは押しても月・市区町村の行が開くだけで、写真は出ない。
- 探す手段が無い。年・都道府県の一覧をスクロールして目で探すしかない。

本 PRD は、カードを横に並べ、カードを選ぶと同じ画面の下に写真が出るようにし、旅・日付・場所のそれぞれに
探す手段を足す。あわせて「場所」と「地図」を 1 つの画面にまとめる。

## 使う人と場面

- 作者 1 人が、家庭 LAN 内のブラウザ（主にデスクトップ、ときどきスマホ）から使う。認証は無い。
- 場面:
  (a) 旅のカードを横に眺め、気になる旅を押してその写真を見る。続けて隣の旅を押す。
  (b) 「去年の夏」「2024年8月」のように覚えている時期から写真を探す。年・月を選んで探す。
  (c) 「松本」のように地名の一部を打って場所を選び、地図とその場所の写真を同時に見る。
  (d) 地図を動かして、その辺りの都道府県と写真を見る。

## ゴール / やらないこと

ゴール:

- 旅・日付・場所の 3 つの眺め方で、カードが横に並び、カードを押すと同じ画面の下にその写真が並ぶ。戻る操作は要らない。
- 日付は、言葉（規則で読み、読めなければローカル LLM で読む）と年・月のピッカーで期間を選べる。
- 場所は、文字を打つと候補が減っていくプルダウンで都道府県・市区町村を選べる。選ぶと地図がそこへ動く。
- 旅は、文字で旅のカードを絞り込み、文字の合う写真を探せる。

やらないこと:

- 写真タブの AI 検索（意味で探す検索。埋め込み・回数上限あり）の変更。ライブラリの検索は文字の一致だけで、AI 検索とは別物。
- Gemini などクラウドの AI を日付の読み取りに使うこと（費用がかかるため。2026-11-02 ユーザー合意）。
- 市区町村をひらがな・ローマ字で探すこと（読みのデータが無い。都道府県 47 だけ読みを持つ。2026-11-02 ユーザー合意）。
- 写真の説明文（`title`・`ai_caption`）での検索（今のコードはこの 2 列を書かない）。
- 旅の区切り方（48 時間の空き）、写真のビューア、★・除外・位置の指定の動きの変更。
- 日付変更線をまたぐ地図の範囲（今と同じく扱わない）。

## 要求

- R1（必須）: 旅・日付・場所のカードを、画面の幅に合わせて横に複数枚並べる。
- R2（必須）: 年と都道府県のカードにも代表写真を 1 枚載せる（旅のカードには既にある）。
- R3（必須）: カードを押すと、一覧を残したまま、その下（場所では地図の下）にそのカードの写真の格子を出す。
  選んだカードは目立たせる。別のカードを押すと格子が切り替わる。「◀ 戻る」は無くす。
  写真が出ているあいだ、カードは横にスクロールする 1 段に縮める（場所の画面を除く）。
- R4（必須）: 月と市区町村は、年・都道府県のカードを選んだときに出る小さなボタン（チップ）にする。押すとその月・市区町村の写真を出す。
- R5（必須）: 「日時なし」と「海外・不明」はカードとして残し、押すと写真を出す。
- R6（必須）: 「場所」と「地図」を 1 つの画面にまとめる。都道府県のカードの列・地図・写真の格子を同じ画面に置く。
  - R6a: 都道府県・市区町村を選ぶと、地図がその範囲へ動く。
  - R6b: 利用者が地図を動かす（ドラッグ・ズーム・クラスタを押す）と、都道府県のカードが表示範囲の中に写真のあるものだけに絞られ、
    枚数も範囲の中の枚数になる。カードや候補を選んで地図が動いたときは絞らない。「全体に戻す」で絞り込みを外す。
    「この範囲の写真を見る」で範囲の写真を出せる。
  - R6c: 旅の「地図で見る」は、この画面をその旅の期間で開き、その旅の写真を下に出し、地図をその旅の点の範囲へ動かす。
    期間は都道府県のカードの枚数・候補・地図の点・写真の格子のすべてに掛かり、解除できる（解除の動きは AC8）。
- R7（必須）: 旅の画面に検索欄を置く。打つと、旅のカードを日時と地名の文字で絞り込む。Enter で、
  文字の合う写真（都道府県・市区町村・地名・ファイル名・撮影日時）を下に出す。
- R8（必須）: 日付の画面に、言葉で期間を入れる欄を置く。
  - R8a: 年・月・季節・正月・GW・お盆・「去年」「先月」「〜年前」「今週」「最近」・範囲（〜、から〜まで）を、決まった規則で期間に直す。
  - R8b: 規則で読めない言葉だけ、LAN のローカル LLM（`llm-vl`）に期間を読ませる。
  - R8c: 読んだ期間を「2025-06-01〜2025-08-31 として検索（規則 / LLM）」のように必ず出し、その期間の写真を下に出す。
  - R8d: LLM が使えないとき・読めないときは「読めませんでした。ピッカーで選んでください」と出す。
- R9（必須）: 日付の画面に、年・月のピッカーを置く。年のカードと月のチップがピッカーを兼ねる。
  年のカードで年全体、月のチップで 1 か月を選ぶ。写真の無い月は押せない。
- R10（あると良い）: ピッカーで続いた範囲を選べる（Shift を押しながら 2 つ目の年・月を押すと、その間を選ぶ）。
- R11（必須）: 場所の画面に、文字を打つと候補が減っていくプルダウン（コンボボックス）を置く。
  - 候補は写真のある都道府県と市区町村だけで、「長野県 松本市（80）」のように枚数を付ける。
  - 部分一致で絞る。都道府県 47 はひらがな・ローマ字（「ながの」「nagano」）でも出す。
  - ↑↓ で選び、Enter で決め、Esc で閉じる。マウスでも選べる。
  - 選ぶと R6a と同じに、カードの選択・地図の移動・写真の表示が起きる。
- R12（必須）: 「除外も含める」は今と同じく、すべての一覧・カード・地図・格子・検索に掛かる。
- R13（必須）: 狭い画面（幅 640px 以下）でも使える。カードの列は横スクロールに、場所の画面は縦に積む。
- R14（必須）: 操作が速く続いても、古い応答で選択や一覧が上書きされない（言葉の読み取りを待つ間に月を選んだ、除外を切り替えた、など）。

## 受け入れ条件

- AC1（R1）: 選択が無いとき、旅と年のカードの容器は `repeat(auto-fill, minmax(220px, 1fr))` で、幅 1280px で 1 行に 4 枚以上並ぶ。
  場所の画面の都道府県のカードは左の列に 2 列で並ぶ。選択があるとき、旅と年のカードは 1 段の横スクロールになる。
  CSS の文字列の検査と画面の試験（容器のクラス）で確かめ、1280px での枚数は実ブラウザで目視する。
- AC2（R2）: `GET /api/admin/library/calendar` の年と `/places` の都道府県に `cover`（`id`・`thumb_url`）が付く。代表の選び方は設計書のとおり。結合テストで、試験データから期待する写真 id と一致することを確かめる。
- AC3（R3）: 画面の試験で、旅のカードを押すと `#lib-detail` が出て `/photos?from=…&to=…` を読み、カードの一覧が残る。別のカードを押すと選択と格子が切り替わる。`#lib-back` が無い。
- AC4（R4）: 年のカードを押すと月のチップが出て、チップを押すと `/photos` をその月の範囲で読む。都道府県と市区町村も同じ。
- AC5（R5）: 「日時なし」「海外・不明」のカードを押すと、それぞれ `untimed=1`・`abroad=1` で読む。
- AC6（R6a）: `/places` の都道府県・市区町村に `bbox`（`[w,s,e,n]`。位置のある写真が無ければ `null`）が付く（結合テスト）。画面の試験で、都道府県を選ぶと地図の `fitBounds` がその bbox で呼ばれる。
- AC7（R6b）: `/places` が `bbox` を受け、範囲の中の写真だけを数える（結合テスト。都道府県の両端に写真があり、範囲が中央だけのとき、その県は出ない）。
  画面の試験で、ドラッグ・ズーム・クラスタを押したあとの移動では `/places?bbox=…` を読み直してカードと枚数が変わり、
  カード・候補の選択による移動では読み直さない。「全体に戻す」で `bbox` が外れる。「この範囲の写真を見る」で `/photos?bbox=…` を読む。
- AC8（R6c）: `/places` が `from`・`to` を受け、その期間の写真だけを数える（結合テスト）。画面の試験で、旅の「地図で見る」が場所の画面を開き、
  `/places`・`/points`・`/photos` のすべてに同じ `from`・`to` を付け、下にその旅の写真（1 ページ目）を出す。解除すると `/places`・`/points` を `from`・`to` なしで読み直し、
  旅の写真の表示は消す（飛んでいる応答も捨てる）。県・市区町村などを選んでいれば、その写真を `from`・`to` なしで読み直す。
- AC9（R7）: `/photos?q=…` が都道府県・市区町村・地名・ファイル名・撮影日時の部分一致で絞る。空白（全角も）で区切った語はすべて合うものだけ。
  `%`・`_`・`\`・`a\%` は文字として扱う。65 文字以上・6 語以上は 400（結合テスト）。画面の試験で、打つと旅のカードが絞られ、Enter で `/photos?q=…` を読む。
- AC10（R8a）: 日付の規則の読み取りが、設計書の表の例（「2024年8月」「去年の夏」「先月」「3年前の正月」「2023年の春〜秋」「去年のGW」「2年前のお盆」「おととしの12月」「最近」「2025年」「今週」「昨年10月から今年2月まで」ほか）を、基準日 2026-11-02 に対して表の期間にする（Rust の単体試験）。
- AC11（R8b・R8d）: 規則で読めない言葉は LLM に送り、偽の LLM の応答から期間を返す。応答が不正（形が違う、from > to、範囲外の年）なら `unreadable`、
  LLM が無い・AI が無効・失敗・失敗後の待ち・枠が使用中・回数の上限なら `unavailable` を返す（Rust の試験、偽サーバー）。規則で読めた言葉は LLM に送らない。
  `Sec-Fetch-Site` が `cross-site`・`same-site` の要求は 403 で、LLM に送らず回数も数えない。
- AC12（R8c）: 画面の試験で、言葉を入れると `/api/admin/library/when` を読み、読んだ期間と読み方（規則 / LLM）を表示し、その期間で `/photos` を読む。
- AC13（R9・R10）: 画面の試験で、写真の無い月のチップが押せない。月を押すとその月、Shift で別の月を押すと間の範囲で `/photos` を読む。年をまたぐ月から月（前後の年ボタンで別の年の月を出して Shift で押す）も同じ。
- AC14（R11）: 画面の試験で、「松」と打つと候補が「松」を含む都道府県・市区町村だけになり、「ながの」「nagano」で長野県が出る。
  ↓・Enter で市区町村を選ぶと、その県のカードが選ばれ `/photos?pref=…&city=…` を読む（県だけなら `pref` だけ）。Esc で閉じる。
  日本語入力の変換中の Enter では決めない。ARIA（`role="combobox"`・`aria-expanded`・`aria-activedescendant`・`role="listbox"`・`role="option"`）が付き、候補の `id` は添字から作る。
- AC15（R12）: 画面の試験で、「除外も含める」を切り替えると、見えている一覧・地図の点・格子・検索をすべて `hidden=1` 付きで読み直す。
- AC16a（R14）: 画面の試験で、言葉の読み取りの応答を遅らせ、その間に月を選ぶと、遅れて来た応答は選択を変えない。
  除外を切り替えたあとに古い一覧の応答が来ても捨てる。
- AC16（R13）: CSS に幅 640px 以下の規則があり、カードの列が横スクロール（`overflow-x:auto`）、場所の画面が 1 列になる。最後に実ブラウザでユーザーが目視する。
- AC17（全体）: `cargo fmt --all --check`・`cargo clippy --all-targets -- -D warnings`・`cargo test` が通る。

## 制約

- サーバーは Rust（`crates/geoframe`）、画面は依存なしの classic script（`web/static/js/library.js`）。描画は `textContent` と DOM API だけ（`innerHTML` などは使わない。`static_files.rs` が検査する）。
- 画面の試験は `cargo test --test admin_ui_library` 経由で回す（node を直接回さない。2026-11-01 の 25GiB 事故）。
- PR は 1 本（目的 1 つに 1 本）。設計書の「実装の順番」をコミットの単位にする。
- ローカル LLM は `ai.json` の `local_base_url`（本番は同じホストの入口 `:8100`）経由で、既存の `AiHttp` の守り（宛先の制限・リダイレクトを追わない・固定ヘッダー・サイズの上限）を通す。ブラウザからは呼ばない（入口は `Origin` 付きを 403 にする）。
- LLM は GPU を他の作業に使っている間は止まる。止まっていても日付の画面は規則とピッカーで使える。
- 費用: 新たな有料の通信は無い。
- 写真は約 3,700 件（公開分）。索引は `taken_at` だけで、文字検索は全件走査でよい規模。

## 決まっていないこと

- LLM に送るモデル名を固定値にするか設定にするか（設計書では固定値 `qwen3-vl-4b-q4_k_m` とし、入口が別名を返すようになったら設定に移す）。
- 本番の `ai.json` の `local_base_url` が `llm-vl` の経路を通す入口か（配布の前に確かめる。通らなければ日付の言葉は規則だけで動く）。
