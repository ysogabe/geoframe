# P5（本番切替）PRD

- 要求の元: [Issue #54](https://github.com/ysogabe/geoframe-ambient-display/issues/54)、[plan.md P5](plan.md#p5-切替pr-6)
- 設計: [p5-design.md](p5-design.md)

## 背景と目的

P0〜P4で、Rust版`geoframe`（単一バイナリ）は検証環境で、本番と同じ写真を使った受入を通った。本番ではまだPython版（`geoframe-server`）が動いている。P5では本番をRust版に切り替え、そのあとPythonの実装と依存をリポジトリと本番から外す。切替の前に、戻し方を演習で確かめておく。

## 使う人と場面

- **ユーザー（管理者）**: 本番の切替に立ち会い、切替の日時と、各段で先に進むかを決める。切替のあとは、管理画面・AI写真検索・旅行ブログを今までどおり使う。
- **miharashi**: 本番機の`http://127.0.0.1:8080`から写真フィードを読み続ける。切替で止まってよいのは、切替の数分だけ。
- **管理者（Claude）**: 手順書に従って演習と切替を行い、結果を記録する。

## ゴール / やらないこと

ゴール:
- 本番でRust版が、Python版と同じDATA_DIR・`catalog.db`を使い、取り込み・配信・管理・ローカルのAIを動かしている。
- 問題が出たら、手順書の手順で数分のうちにPython版へ戻せる。その戻し方を検証環境で演習している。
- 切替のあと、Pythonの実装・依存・CIのジョブ・unitがリポジトリから無い。Rust版のビルドとテストはPythonを要さない。

やらないこと:
- クラウドのAI（Geminiの写真比較・撮影地の候補）を切替と同時に有効にすること。切替の数日後に、日の上限を小さくして有効にする（P5のPRの外の運用作業。§決まっていないこと）。
- PythonのAIを有効にしたまま戻すこと（戻すときはAIを無効にする。2026-10-29 ユーザー決定）。
- 初回のEmbeddingを本番のコピーで先に済ませること（切替のあと意味検索が約48分503になるのを受け入れる。2026-10-29 ユーザー決定）。
- 画面の作り直し、新機能。

## 要求

- R1（必須）: 本番でRustが書き込みを始められるようにする。検証環境のためのガード（`/etc/geoframe/staging`の印）を外し、PythonとRustが同時に書かない守りを手順と`Conflicts=`で持つ。
- R2（必須）: 本番へRustのバイナリを配る手順と道具。誤って稼働中のPythonの足元へ配れない。配布の前の版に戻せる。
- R3（必須）: `catalog.db`のバックアップから復元する手順と、その演習。
- R4（必須）: 切替の手順書。止める順・設定（`/etc/default/geoframe`）・確かめること（スモーク・miharashi・AIの状態）・止める判断の基準。
- R5（必須）: Python版へ戻す手順（AIは無効）と、戻したあとRustへ切り替え直す手順。両方を検証環境で演習する。
- R6（必須）: 本番のコピーを使った通しの演習（シャドー比較を含む）を、本番に入れるのと同じバイナリで済ませてから本番へ入れる。
- R7（必須）: ユーザーの立ち会いのもとでの本番の切替と、その記録。
- R8（必須）: 切替のあと、Pythonの実装と依存を外す。Rustのビルドが読む画面のファイル・旅程を移し、Pythonを呼ぶテストを外し、CIのPythonのジョブと文書を直す。
- R9（あると良い）: 切替のあと数日の確認項目（Decisionの全件再判定の終わり、索引の公開、バックアップのtimer）と、クラウドAIを有効にする手順。

## 受け入れ条件

- AC1（R1）: `GEOFRAME_INGEST=1`のRustが、印の無い機体でも起動して書く。ガードのコード・試験用の環境変数・文書の記述が残っていない（`grep -rn "検証環境の印\|GEOFRAME_TEST_STAGING\|GEOFRAME_TEST_PYTHON_STATE" crates deploy docs`が、記録の文書を除き0件）。`geoframe-rs.service`の`Conflicts=geoframe-server.service`で、一方を起動すると他方が止まることを検証環境で確かめた。
- AC2（R2）: 配布の道具は、相手の機体でPython版が稼働中なら何も変えずに断る。本番へ配るには明示の指定が要る。配布の途中で失敗したら前の版へ戻る。試験（`rust-deploy-test.sh`）が通る。
- AC3（R3）: 検証環境で、バックアップ（`latest.db.gz`）から復元して起動し、`integrity_check`がok、`.dump`のSHA-256がバックアップと一致、配信の件数が復元前と同じ。
- AC4（R4・R6）: 検証環境で、新しい本番のコピーを使い、手順書のとおりにPython→Rustへ切り替えた。シャドー比較（`tools/compare_with_python.py`）で想定外の差が0、miharashiの読み取りが続き、取り込みの1サイクルとローカルのAIが動いた。結果を`p5-acceptance.md`に記録した。
- AC5（R5）: 検証環境で、Rust→Python（AI無効）へ戻して配信・管理操作が動き、手動の位置・お気に入り・除外・回転が保たれた。そこから再びRustへ切り替えて動いた。品質の切り戻し（[server.md §16.10](server.md#1610-rustで作った結果をpythonへ切り戻すp5のロールバック)）の件数・行数・グループ数を記録した。
- AC6（R7）: 本番で、切替の前のバックアップを取り、手順書のとおりに切り替えた。`/healthz`と`/api/v1/photos`が200、件数が切替の前と同じ、miharashiの表示が続き、取り込みのサイクルが成功した。記録を`p5-acceptance.md`に残した。
- AC7（R8）: リポジトリに`app/`のPython・`requirements*.txt`・`geoframe-server.service`・Python版の配布手順が無い。`cargo build`・`cargo test`・CIがPythonの導入なしで通る（標準ライブラリだけの`deploy/loc_decision_morning.py`とその試験、文書の検査は除く）。画面のファイル・旅程は新しい場所から埋め込まれ、配る画面は切替の前と同じ。
- AC8（R9）: 切替のあとの確認項目とクラウドAIの有効化の手順が`plan.md`・手順書にある。

## 制約

- 本番機（この開発機と同じ機体）では、ユーザーの立ち会いと各段での明示の許可なしに、サービスの停止・起動・配布・`/var/lib/geoframe`への書き込みをしない。本番の`catalog.db`に直接つながない（読むのはバックアップのファイル）。
- 秘密情報・LANのアドレス・写真のファイル名・座標・地名は、リポジトリ・文書・PRに書かない。
- PythonとRustが同時に`catalog.db`へ書かない。
- 切替で配信が止まるのは数分まで。意味検索の503（約48分）と、Decisionの全件再判定で本番機のCPUを約4時間使うことは受け入れ済み。

## 決まっていないこと

- 本番の切替の日時（検証環境の演習のあとにユーザーと決める）。
- クラウドAIを有効にする日と日の上限（切替の数日後。ユーザーが決める）。
- 本番の`/etc/default/geoframe`に足す値（AI設定のJSONの中身・`GEOFRAME_TILE_UA`など）。値は切替の準備でユーザーと確かめる。
