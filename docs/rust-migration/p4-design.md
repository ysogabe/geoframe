## 3. 設定・起動

既存`GEOFRAME_AI_ENABLED`・各周期上限・検索上限・`GEOFRAME_LOC_SUGGEST*`を対応付ける。新しい設定は環境変数でなく、**任意の`GEOFRAME_AI_CONFIG`が指す小さなJSONファイル**に用途別routingと空間識別をまとめる。バイナリ＋設定＋データの配布方針を維持する。

- ファイル未指定: 新しい外部AI呼び出しは無効。既存フィード・画像・管理、保存済み推薦の読み取りは継続する。`AI_ENABLED=0`のE6は現行どおり503。
- 明示したファイルが不正: 新しいAI呼び出しだけを無効にして起動し、STATUSに`ai_config_invalid`と件数だけを示す。写真配信・管理は継続する。値・パスはログに出さない。最大64KiB、通常ファイル、既知のキーだけ、重複キー拒否。
- 構造: `local_base_url`、サービスID、`tasks`（`image_embedding`、`query_embedding`、`photo_judge`、`location_clue`、`location_suggest`）ごとの`provider/model/allow_cloud/daily_request_limit`、接続契約確定後の`embedding_space`。秘密はファイル内に埋めず認証ファイルのパスを指定する。
- `allow_cloud`の既定false。`provider=cloud`でも許可が無ければその用途はpolicy_disabled。画像と検索語の許可は独立。`location_clue`はLANのDecisionに限定する。
- `GEOFRAME_EMBED_BACKEND=local`はRustで推論エンジンを起動する意味にしない。旧設定値は旧データの表示用識別にだけ使い、新規呼び出しには明示したroutingを使う。廃止するCPUモデル用設定は文書化する。
- AIワーカー: `GEOFRAME_INGEST=1 && GEOFRAME_AI_ENABLED=1 && 有効な用途あり`の時だけ起動。`Ingest.writer`と`LockHold`を共有する。読み取り専用起動でテーブル作成・job回収・結果保存を行わない。writerが無い起動ではクラウドのquery_embeddingもpolicy_disabled（定型503）とし、予算を迂回して送らない。LANの文Embeddingと適合するメモリキャッシュの利用は許す。
- 設定変更は再起動で適用する。設定ハッシュと用途のポリシー版は送信可否の検査・監査用に保持するが、結果の冪等キーには入れない。実際の送信前に現在の設定を再評価し、結果確定時は結果のモデル・処理版と入力世代を照合する。タイムアウト・URL・別用途の許可だけを変えても成功結果を再送しない。

既存ランクモデルは`GEOFRAME_RANK_MODEL`を維持。既存JSON形式をサイズ・数値範囲・有限数で検証し、未配置なら既存の固定式を使う。不正な明示ファイルは定型エラーで検知し、ユーザーの重みを黙って別の意味へ読み替えない。

## 4. 永続ジョブと並行処理（最初の実装の中心）

### 4.1 ai_jobs

仕事は起動時と各AI周期のreconcileで、現在の写真・有効な結果から導く。取り込みイベントだけに依存しない。既存データ、Python切り戻し中の追加、後から有効にした用途も自動的に対象になる。現在の結果表に適合する答えがあれば、jobを作る前と送信前に再利用し、job行の有無だけで再計算を決めない。`ai_jobs`は進行・再試行を記録する表とする。

既存DBへ追加する。ジョブは`image_embedding`（画像のSHA単位）、`location_clue`（写真単位）、`location_suggest`（日・写真集合単位）、`photo_judge`（グループ・候補集合単位）。検索語のリアルタイムEmbeddingはメモリキャッシュで扱い、永続キューに入れない。ルールだけのグループ再構築はローカル処理として入力世代を検査する。位置候補のクラウド回答は受信後にphoto_loc_runsへ保存してlocation_suggestを完了し、座標化は別のlocation_geocodeジョブ（保存済み回答を参照）へ分ける。Nominatimの失敗で有償回答を捨てたり、Geminiへ聞き直したりしない。

保持する項目:

- `id`、`kind`、内部対象キー、`input_hash`、`processor_version`（用途のmodel/revision・prompt・前処理・space_id等、結果を左右する識別）。
- `state`、実際の失敗回数`attempts`、`next_attempt_at`、`interruption_count`、`defer_count`、起動IDとランダムな`claim_token`、作成・更新時刻、定型の`last_error_code`。設定・ポリシー版は監査項目。
- 冪等キーは`(kind,target_key,input_hash,processor_version)`。enqueueは重複を増やさない。画像やプロンプトの本文をjob行に保存しない。設定で許可されない用途はenqueueを見送り、状態の集計で無効と示す。

状態は`pending/running/deferred/succeeded/failed/obsolete`。成功結果の確定と`succeeded`は同じトランザクション。古い入力・結果を左右する処理版になったジョブは`obsolete`、新しい入力は別ジョブ。送信許可が無い間は送らず、設定の解禁だけで過去の成功結果を積み直さない。成功済みの同じキーは再課金のためにリセットしない。

### 4.2 claim・確定

1. writer上の短いトランザクションで実行可能な1件をclaimし、起動IDとtokenを付ける。
2. writerの外で写真・入力を読み、縮小・EXIF除去・入力SHAの確定、送信ポリシーとavailableの再確認、HTTP要求を行う。送信の直前にもDBの行・入力世代・現在のhiddenを読み直し、更新・削除済みなら送らない。クラウド画像送信はhiddenの写真を既定で除き、許可は用途別の`include_hidden`（既定false）で明示する。
3. writer上でtoken・入力世代・結果を左右する処理版を再確認して結果を確定する。失効したtokenの遅延応答は保存しない。
4. 画像の入力世代は`photo_id/display/md5/mtime/rotation`と有効な品質特徴量の`content_sha256`。写真集合は構成員・各世代・撮影時刻・処理版の順序を固定したハッシュ。位置候補では`lat IS NULL`も確定条件にし、待機中の手動SAVEを上書きしない。

T4.6bのLAN専用clue判定は、現行Pythonと同じくhiddenで対象を絞らない。上の既定のhidden除外はクラウド画像送信の規則で、日単位の候補要求時に独立して再検査する。旧clueには質問版・rotation・品質SHAの由来が無いためRustの検証済み結果へ自動移行せず、LANで再判定する。Rustの処理版・入力世代は追加表に保持し、Python互換clueと一緒に確定する。

表示画像はDriveのderivativeだけでなく、ローカルJPEG/PNGの原本を直接指す場合もある。DATA_DIR内の読み取り用パス検査を使い、削除用のderivative_fileだけを読み取りの安全性の根拠にしない。画像を読み終えたらロックを解放する。既に向きが適用されたderivativeへphotos.rotationを重ねず、直接表示する原本だけはEXIF向きを一度適用してからsRGB化・縮小・新規JPEG化する。

AIのHTTP・画像準備・ベクトル計算中にwriter、画像用ロック、DBトランザクションを保持しない。必要な画像の読み取りだけを既存の画像ロック内で完了してから処理する。背景AIワーカーは1本、背景の外部AI要求もProviderごと1件を基本とする。画像／文Embeddingには別の対話用1枠を予約する。利用不可の用途を後回しにした後は、別の利用可能な用途を進める。

### 4.3 再試行・停止

| 状況 | 扱い |
| --- | --- |
| available=false、停止、GPU lease、到達不能 | `deferred`。写真の不良ではない。失敗回数を増やさず、Provider単位とjob単位のnext_attempt_atを60秒後以降へ進める |
| 429 | `deferred`。Retry-Afterを60〜3600秒に収める。本文は保存しない |
| 認証tokenを1回更新しても続く401、403、モデル404、Provider全体の契約不一致 | Provider・用途単位で一時停止。理由コードをSTATUSへ出す。設定修正・管理CLIによる解除まで新しい要求を出さず、全jobをfailedにしない。停止はDBに記録し再起動だけでは解除しない。認証等の関係する設定が変わった場合か、管理CLIの明示解除後に検証し直す |
| 特定jobの入力サイズ超過・恒久的な不正 | そのjobだけ`failed`。後続は進める |
| 応答構造不正等のjob失敗 | attemptsを加算、60/120/240/480秒、最大5回で`failed` |
| availableでも同じjobだけが反復して5xx/時間切れ | defer_countを記録。他jobの成功がある、またはDiscoveryがavailableを返している状況で3回反復したら、3回目以降の各失敗をattemptsへ加算し、5回でfailedとする。単独で最後に残ったjobも打ち切る。後回しのjob自身を待ち行列の後ろへ回す |
| クラウドへの送信後の時間切れ・5xx | 課金され得る試行としてattemptsと送信予算に数え、最大5回で停止。到達しなかった明白な接続失敗とは区別 |
| 写真・候補集合・処理版が変わった | `obsolete`。古い結果を確定せず、新しいキーで作り直す |

Providerごとの待機時刻で要求の連打を避ける。起床周期は既存の最小30秒を維持。時刻はUTCで永続化し、バックオフ計算は注入可能な時計で試験する。手動再試行は`geoframe ai-jobs retry`相当のCLIを用意し、failedだけを対象に現在の入力・ポリシー・既存結果を再検査する。Provider一時停止の明示解除もCLIで行う。いずれもサービス停止後だけ利用し、既存と同じガード・`.ingest.lock`・writerを通す。稼働中は拒否し、クラウド許可を迂回しない。

実行権の時限leaseは設けない。`.ingest.lock`で守る1プロセス・1背景ワーカーに限定するため、起動IDとclaim_tokenで所有を識別し、再起動でロック取得後に旧起動のrunningを回収すればよい。古いtokenからの確定は拒否する。GPU側のleaseとは別の概念。

予期しない中断を回収する際はinterruption_countを加算し、3回で`failed/interrupted`としてそのjobを隔離する。正常な停止ではjoinの待機中はtokenを保ち、有効な応答の確定を許す。待機期限で未完了のものをwriter上で`deferred/shutdown`へ戻してtokenを失効させる。起動IDごとに停止開始も記録し、終了直前に書けなかったものは次回回収で予定された中断と区別する。panic等は当該jobに記録し、同じjobが全AIを塞ぐ無限ループを防ぐ。

SIGTERMを受けた時点で共有StopFlagを立て、新規claim・送信を止める。HTTPのgraceful shutdownが終わってから合図する現行の順序は改める。待機中に届いた有効な応答は、writerが動いていてtoken・入力・処理版・送信許可が有効なら確定してよい。停止を理由に受信済みの有償結果を一律に捨てない。

AIのjoinは既存と同じ最大10秒。HTTP終了、タイル掃除、同期、AI、キャッシュ保存、runtime停止の全体でSIGTERMから60秒の共通期限を使い、各処理へ残り時間を渡す。unitは`TimeoutStopSec=90s`を明示する。待ち切れないHTTPはプロセス終了で打ち切り、次回回収する。残るスレッド（期限後も始まったSQLを続けるDB書き込みスレッドを含む。接続を閉じてから手放す）はLockHoldを保持し、2つ目の書き手を作らない。タイミングを偽時計と停止結合試験で確認する。

送信予算は追加の`ai_request_usage`（用途・UTC日付・周期窓）へ永続化する。UTC日は固定窓、周期窓は直近`cycle_secs`秒のローリング窓（履歴のキーに窓の長さを含めない。周期の設定変更や以前の固定窓の行でも消費を失わない）。履歴の最新時刻より前の時計での予約は拒否し、古い行の掃除や再起動をまたいで枠が復活しない。既存の周期件数上限に加え、クラウド用途は`daily_request_limit`を必須にし、未設定／0なら送らない。外部送信の直前にwriterで枠を予約し、失敗・中断しても消費を巻き戻さない。対話検索の予約は期限付き（最大200ms）で試み、writerが忙しければ定型503を返して送信しない。期限を過ぎたキュー内の予約操作は実行しない。予約完了と呼び出し側の終了が競合した場合も送信せず、予算は保守的に消費済みとしてよい。再試行・対話検索・再起動をまたいでも上限を超えない。これは金額の保証ではなく、課金され得る要求数の上限。

外部要求は少なくとも1回となり得る。タイムアウト後の再試行によるクラウドの重複課金を完全には防げない。DBへの二重確定を防ぐことと、外部課金の一度きりを保証することは区別する。

## 5. Provider境界と安全面

能力ごとの薄い境界を使い、全用途を1つの巨大traitへ押し込めない。画像・文Embeddingは結果に`SpaceIdentity`、Decisionは型付きのclue結果、Geminiは検証済みの判定／候補を返す。

- local-model-lab: 設定したLAN入口だけへ接続。`GET /llm/catalog`、`GET /llm/services/<id>`のavailableと能力を確認し、`X-Client-Name: geoframe`を送る。確認は予約ではないので、直後の失敗も処理する。GPU管理APIは呼ばない。
- Discovery応答は能力・状態の確認に使う。返された任意のホスト・URLを写真の送信先として採用しない。APIパスは実装で許可したものと照合する。
- Decision: `/llm-decision/health`と`/llm-decision/v1/systemone`。画像対応readyを確認する。1536px画像は1.6メガピクセル以下にも収める。未判定・実行中・一時的な利用不可が残る日は待つ。恒久エラー／上限到達の写真は判定済み・手がかりなしとして記録し、その画像を送らず日全体は進める。位置候補のクラウド送信前にもDecisionのavailable・画像対応readyを確認し、Decision停止中は保存済みclueだけを理由に送信を進めない。正常に判定され手がかり閾値を満たす写真だけを位置候補の送信対象にする。
- クラウド: 既存Vertex系のGemini契約を基本に、認証・プロジェクト・リージョン・モデルを明示する。Drive鍵への暗黙フォールバックやADC探索を新設しない。既存のサービスアカウント認証のRust実装を調査し、scopeと宛先を分離して再利用する。tokenキャッシュのキーはcredential識別・scope・audienceで分け、DriveとVertexで取り違えない。
- T4.6aの調査で接続先を確認（2026-10-27、[Googleの公式資料](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/locations?hl=en)）。`us`/`eu`は既存Pythonと同じ`aiplatform.{location}.rep.googleapis.com`、`global`は`aiplatform.googleapis.com`、通常リージョンは`{location}-aiplatform.googleapis.com`。検証済みの識別子から固定HTTPS宛先と`generateContent`パスを組み立て、公開IPだけへ接続する。任意URL・鍵JSONの`token_uri`は採用しない。OAuth交換先とJWT audienceは`https://oauth2.googleapis.com/token`、scopeは`cloud-platform`に固定する。
- token交換は推論の送信予算に数えない。用途の許可・停止を確認してからtokenを取得し、推論POSTの直前に予算を予約する。401後はtokenを1回更新し、再送にも1枠を予約する。token交換の待ちは最大10秒かつ用途全体の期限内、キャッシュのロックは外部I/O中に保持しない。推論の最初の書き込み前に判明したDNS・接続失敗はジョブの失敗回数を増やさず待機し、予約済み枠は戻さない。Drive専用の待機付き再試行を有償推論へ流用しない。
- 接続先は管理者設定のみ。URLのuserinfo・query・fragment、想定外schemeを拒否。クラウドは実装が組み立てる固定HTTPS宛先。LANのHTTPは許可するが、ユーザー入力のURLは受け取らない。LAN入口は接続時にprivate/loopbackの解決先へ固定し、公開アドレス・解決先の途中変更へは送らない。クラウドのregion/project/modelは用途ごとの許可文字・長さを検証して組み立て、パスやホスト名への任意文字列の挿入を防ぐ。
- **AI専用agentはリダイレクト上限0にし、3xxを契約不一致として扱う**。本文や認証情報が別の宛先へ転送されないようにする。既存net::agentのプロキシ自動読込をそのまま使わず、LANはプロキシを無効にする。クラウドのプロキシは管理者が明示した場合だけ。
- 外部通信はwriter外の専用処理。Discoveryは2秒、対話的な文Embeddingは15秒、背景処理は用途別60〜180秒。接続は5秒まで。対話Embeddingの予約枠は背景の排他で塞がず、最大1要求を背景と並行して受け付ける。待っている対話要求を新しい背景要求より優先する。#93の受入に「背景1件＋新規文1件で文の応答15秒以内」を含め、上流が直列実行で満たせなければ、上流の優先制御・別実行枠が整うまで接続完了にしない。対話枠自身が満杯なら定型503で返し、HTTPワーカーは塞がない。
- 入力画像は長辺768pxのJPEG q82、位置候補・Decisionは最大1536pxのJPEG q88を基本にする。元画像・EXIF・GPS・ファイル名・正確な座標を送らない。プロンプトに必要な情報は用途ごとに固定し、位置候補の日付等の送信項目も設定説明へ記載する。
- JSON送信はbase64込み8MiB以下、応答は展開後1MiB以下（既存の圧縮前制限も適用）。バッチや上流のさらに小さい上限は契約確定後に優先する。
- 失敗ログとjob.errorはenum・HTTP状態・件数だけ。URL・例外本文・検索文・モデル応答を記録しない。job対象キーもAPI・ログへ露出しない。

## 6. 索引・旧データ・切替

### 採用されたEmbedding接続契約（2026-10-27、T4.4）

local-model-labの[#101](https://github.com/ysogabe/local-model-lab/pull/101)が反映され、[#93](https://github.com/ysogabe/local-model-lab/issues/93#issuecomment-6444034979)の画像対応APIを確認した。仕様の参照は同リポジトリの`c9b05b590d838b81a6b2f939af34e409f16469ad`、`docs/guides/resident-image-embedding.md`と`scripts/embedding_server.py`に固定する。以前のtext-onlyという記述は当時の状態であり、この契約を確認した構成に限って画像を送る。

- 設定したLAN入口と固定パス`/llm-embed/v1/embeddings`、service_id=`embed`を使う。Discoveryと`/llm-embed/v1/models`の画像・文章能力、実際の応答modelを照合する。
- model=`embeddinggemma-2-bf16`、重みrevision=`914f7f89142e33e77833254d9c9b90c3cef7303b`、768次元、L2正規化。上流はBF16のため、受信後も既存のベクトル検査・L2再正規化を通す。旧Q8_0名は入力aliasとして受理されるだけで、新空間の識別に使わない。
- JSONの`input`は文章、`{"image":"data:image/jpeg;base64,..."}`、またはその配列。画像は既存の安全なRGB由来JPEGだけを渡す。要求全体はbase64込み4MiB以下、バッチは最大8件。画像ジョブは原則1画像ずつ送り、対話検索を長いバッチの後ろに並べない。検索文の接頭辞は`task: search result | query: `で、画像には付けない。
- 応答は`data[index].embedding`。revision・前処理版・共通空間IDを独立フィールドでは返さないため、§6.2の固定契約設定で識別する。重みrevision、固定サーバー処理、クライアントの画像縮小/JPEGと検索文前処理の版を区別し、設定や実能力が契約に合わなければ送信・保存しない。モデル名や768次元だけから版を推測しない。
- 上流は逐次処理。背景1枠・対話1枠と15秒の条件を変えず、LXCで両要求の並行成功を確認してから接続完了とする。長時間負荷やCPU画像APIの計測を実施済みとは扱わない。

### 6.1 保存形式

現規模は約6,500枚・768次元で、float32のベクトル本体は約20MiB。最初はSQLiteのfloat32 LE BLOBと線形コサイン検索で十分な規模と判断する。ANNサーバーや別のベクトルDBは導入せず、LXCで時間とRSSを測り、必要なら後で検討する。

追加する表の責務案:

| 表 | 主なキーと役割 |
| --- | --- |
| `ai_jobs` | §4の永続ジョブ |
| `ai_embedding_spaces` | space_idとmodel_id/revision/preprocess_version/dimension/normalization。画像変換と検索語promptの版を含む。タプルの一意性を制約 |
| `ai_embedding_vectors` | `(space_id,input_sha256)`。生成・検証済みの画像ベクトルを再利用 |
| `ai_scene_groups` / `ai_scene_members` | space_idと入力集合の世代を持つグループ・代表・順位・判定。旧表を上書きしない |
| `ai_request_usage` | 用途・日・周期の送信数。再起動でも上限を維持 |

`ai_indexes/ai_index_members`は作らず、索引の顔ぶれは現在の`photos`→有効な`photo_quality_features.content_sha256`→`ai_embedding_vectors`の結合で導く。ベクトルのキーのinput_sha256は品質特徴量の元derivativeのSHAとする（変換規則はspaceの前処理版に含める）。画像変換後の実際の送信バイトのSHAも検証・監査用に保存する。active pointerは`settings.ai_active_space`。

追加のai_*表は既存`REQUIRED_SCHEMA`へ一律追加しない。取り込み無効で旧PythonのDBを読むとき、表が無ければ新空間なしとして既存の写真配信・旧結果読み取りを続ける。表の作成はガード後のwriter移行だけで行う。

位置候補は既存`photo_loc_clues/runs/suggestions`の意味を保ち、必要な入力・処理版・ポリシー版の付帯情報を追加表で保持する。保存結果の有効性は、その付帯情報と現写真の世代で検査する。候補の互換投影とjob完了は同じトランザクション。Pythonと同じ用途・モデル・promptなら`run_id_for`の式・prompt_version・modelと`_reusable_run`の再利用規則をfixtureで一致させる。既存の日の写真が減った場合は、送信済み写真の世代が同じことを条件に部分集合を再利用し、手動SAVEのたびに再課金しない。異なるpromptの結果は別の由来として保持し、旧列を偽の版で上書きしない。試行の正はai_jobsとし、Python互換attempts列は同じトランザクションで更新する投影にする。具体的な列・索引・制約は担当タスクでschema.rsへ定義し、テストで固定する。

T4.6cは保存・再利用のrepository（c1）と実行／座標化の接続（c2）に分ける。Python互換のrun_idはprompt版・model・ソートした送信IDから導き、実際の写真番号には別途保持する送信順を使う。Rustの結果キーには日集合と各写真の入力世代・処理版も含める。同じPython run_idが異なる入力世代に再び現れても、過去の有償回答は追加表の別履歴として残す。互換投影前に既存回答を失わないことを確認する。

旧done runだけでは画像世代を証明できないため、現世代の検証済み回答へ自動昇格しない。同じmodel・prompt・run_idまたは部分集合の旧done runがある場合、旧回答／候補を残し、由来不明のまま自動で再課金して置き換えず保留する。旧errorのattemptsも自動でゼロへ戻さない。Rust由来の部分集合再利用では、残存構成員と送信済み写真の画像世代を照合する。送信済み写真が手動SAVEで対象外になっても、その画像世代が同じなら再利用を妨げない。画像の変更・削除を、未変更と推測しない。

クラウドの日集合はinclude_hiddenの許可範囲から作り、既定で除外したhidden写真は送信画像にも未判定待ちの集合にも含めない。その集合のPendingが残れば送信しない。Failedは手がかりなしとして送信画像から除き、正常なReadyの通過写真だけをlandmark優先・clue降順・ID順で最大6枚選ぶ。写真番号のラベルもPythonの「写真1」等と固定prompt／schemaを維持する。送信直前の画像世代・現在の許可はtoken取得や401更新で待った後にも再確認する。

保存済み回答の座標化はCloudClient・token交換・クラウド推論の予約枠を使わない。既存location_suggest用途の有効／無効・停止とCLIガードを尊重し、Nominatimの正常な0件と通信障害を区別する。通信障害は座標化だけを再試行し、正常な0件は再課金の理由にしない。GeocoderとキャッシュはGET地名検索と同一のものを使い、新たな地名問い合わせの直前にも停止を確認する。候補への投影時は現世代・latNULLを再照合し、photos一次列には書かない。

### 6.2 同じ空間の条件と公開

- `SpaceIdentity`は上の全項目に加えProviderが保証する共通の画像／文空間IDを持つ。名前や次元だけでは一致とみなさない。版を返さないProviderには契約で固定した版の設定が必要。版が判別できなければ接続を有効にしない。
- ベクトルは次元・有限数・非ゼロnormを検証し、正規化規則に従って保存。Rust側の任意の768次元固定値へ切り詰めない。最大4096次元、検索語も同じ識別を検証する。
- 新しい空間へ別に構築する。構築開始時の対象集合のうち現在も有効な写真について、現入力・処理版のimage_embeddingがfailedとなったものは意味検索・グループの対象から除き、それ以外のベクトルがそろったら、その集合ハッシュとカバレッジを確認して`ai_active_space`を原子的に切り替える。構築後の追加は待たせず次の周期で処理する。更新・削除された構成員は公開対象から除き、再生成は後続で行う。変更が続くために全公開を永久に待たせない。failedは対象から除外した件数・理由をE5.pipelineへ出し、手動再試行の成功後は次の差分で検索・グループへ加える。全件失敗を完成扱いにせず、成功ベクトル1件以上かつ切替時の有効対象に対する成功率がactivation_min_coverage（設計案の既定0.95）以上のときだけ自動切替する。閾値未達は旧空間を保持して管理確認を要する。
- 同じ空間へ写真が増えた時は、新しいベクトルが保存された時点で有効JOINにより検索対象へ入る。毎回の全索引スナップショットは作らない。グループは影響のある時刻窓の世代を再検査して更新する。
- 空間切替は検索の切替であり、選別・表示抑止の切替ではない。有効な旧選別は別の選別ビューとして保持する（§6.3）。クラウド判定が未許可でも意味検索の切替はでき、旧選別を一斉解除しない。
- フィード・管理・検索はactive pointerと本体を同じ読み取りトランザクション、または同じSQLのJOINで読む。古い結果を掃除する場合も別トランザクションで行う。P4の自動GCでは旧有償結果を消さない。
- 新規・更新された写真に有効なAI結果がまだ無い間も、フィードでは簡易品質で表示する。意味検索の対象数と待ち件数は有効JOINの実数を示す。
- 検索用LRU 64件のキーは`space_id + query_preprocess_version + normalized_query`。空間変更で古い文Embeddingを流用しない。

### 6.3 旧データと切り戻し

旧`photo_ai_features/photo_embeddings/photo_ai_groups/photo_ai_group_members`を保存する。旧Embeddingはrevision等が無いため、既定で`legacy-unverified`として新しい空間へ輸入しない。旧モデルと同名のProviderでも新しい検索語ベクトルを掛け合わせない。

- 新空間が無い間は旧判定・グループをフィードと空検索へ使える。旧モデル内の保存ベクトル同士の構図比較は継続できるが、新しい検索語ベクトルとの比較は行わない。
- フィードの表示抑止は検索空間とは独立した選別ビューで行う。現写真・現画像と`photo_ai_features`のdisplay/md5/mtime/content SHAが合う旧判定を保持する。グループ内に現在も存在して表示可能かつ世代の合う推薦写真が1枚以上ある場合だけ非推薦を抑止する。代表の削除・更新・hidden化で残りの場面全体を隠し続けない。favoriteは常に表示を優先する。この世代・代表存在の検査は現行AI_VISIBLEに対する意図した修正なので、同じDBの複製で導入前後のフィード件数とsuppressed差を記録し、変化を対象の不整合で説明する。管理画面のsuppressed/groups/group_pendingも同じ選別ビューから数える。
- 空間を切り替えるだけなら、この有効な旧抑制集合は不変。新しい同一場面候補を作っただけで旧選別を破棄しない。新判定で置き換えるのは入力集合・世代が一致する選別単位、または有効な既存選別と重ならない新しい集合に限る。旧選別と部分的に重なる新集合は結果を保持して管理確認の対象とし、自動的に抑止を置き換えない。
- 過去の有償判定の再利用はモデル・prompt・入力集合の由来で決める。写真ごとの品質・keep_score等は世代が一致すればベクトル空間と独立して使える。証明できない結果も消さない。
- Pythonは追加表とactive pointerを使わず旧表を読む。旧Embedding・選別表を新モデルで上書きしないため、切り戻しでは旧結果を利用できる。Rust期間に追加された写真は品質で表示し、PythonのAIワーカーが追い付く。一次データは巻き戻さない。
- 旧結果参照へ戻すCLIもサービス停止後にガードとロックを通す。Python→Rustで再切替したらreconcileが追加・変更分を拾う。新結果表を消す必要はない。位置候補は上記のPython互換run_idと試行数の投影を試験し、再課金を避ける。
- 旧空間を検証済みとして明示宣言する道は、モデル・重み・画像／文前処理の版と実測照合がそろう場合だけ。単に旧モデル名を設定しただけでは許可しない。根拠が無ければ#93で新しく構築する。

## 7. 選別・位置候補・API

同一場面は既存の時刻窓15分を出発点に、空間ごとのしきい値で連結成分を作る。pending/running/deferredの画像が残る窓の確定は待つ。現入力・処理版のEmbeddingがfailedの画像は候補集合から外して窓を確定し、再試行成功後に再構築する。除外された画像もフィードでは簡易品質で表示でき、途中で出来た組で写真を隠さない。代表はルール／既存の重みを基本とし、Gemini比較結果が有効なときだけその結果を使う。未判定の同一場面候補を新たな自動非表示の根拠にしない。

位置候補は既存の12時間・日付の区切りと最大6枚を出発点にする。Decisionのpending/running/deferredが残る日は待つ。failedに達した写真は判定済み・手がかりなしとして画像を送らず、ほかの正常な手がかり写真による推定は進める。候補の座標化は既存GeocoderのNominatim入口と全体1秒1件の制限・UA・キャッシュを共有し、並行処理で制限を二重化しない。地名は外部に問い合わせるデータであることを用途の説明に含め、ログには出さない。結果の採用は既存setlocだけが行う。

E5/E6は既存のJSON形・並び規則・mode・入力検査をfixture化する。同じ固定ベクトル・同じグループを与えた場合はPythonと比較し、新しいAI出力の数値一致は要求しない。新しい待機件数・理由はE5の`pipeline`内へ加え、既存フィールドの型を変えない。

| 項目 | 旧結果参照 | 新空間が有効 |
| --- | --- | --- |
| E5 photos / eligible / pending_embeddings | 旧モデルの有効行・現在の対象SHAを従来の定義で数える | 有効JOINでactive空間の画像SHA数・現在の対象SHA数・不足数 |
| E5 judged / recommended / groups / group_status | 世代が合う旧選別結果を集計 | 同じ選別ビューの有効結果を集計し、新検索空間の件数とは分けてpipelineへ示す |
| E5 embedding_model / embedding_backend | 旧値を継続表示 | active空間のmodel_idと`local_http`等のProvider識別文字列 |
| E5 other_model_embeddings | 他の旧モデルの有効なdistinct SHA | active以外の保存済み空間と旧結果にあるdistinct SHA（空間間の同じSHAは重複計数しない） |
| E6空検索の順位・カード | 世代の合うkeep_score、無ければ品質点。favorite等の既存タイブレーク | 同じ。keep_score/aesthetic_score/recommended/reasons等は世代が合う既存の写真別判定を再利用し、無い値は既存のnull/空配列規則 |
| E6構図まとめ | 同じ旧モデル内のベクトルだけで比較 | 同じactive空間内のベクトルだけで比較 |

新空間の未構築時は意味検索503。P5へ進む前に実APIと索引・日本語意味検索を準備し、この状態を本番の定常動作にしない。HTTPの未知パスやHost検査・CSRF等は既存の入口を使う。

## 9. 検証とリスク

- PRDのP4-AC1〜9・10a・10bを試験の索引にする。最初にjob状態遷移・入力世代・ポリシーのスタブ試験を作る。
- Python比較は、固定モデル出力・合成DB・公開の架空地点を使う。新索引のある状態／無い状態、索引切替中のフィードと管理APIを比べる。
- LXCの専用DBで、本物のLAN ProviderのDiscovery・停止相当の到達不能・復帰、miharashiと管理操作を通す。モデルサービスを止める代わりにGEOFRAMEの試験用接続先を使って到達不能を再現し、共有GPUの他利用者に影響させない。
- 実クラウド試験は、送信用途・費用の許可が得られた後だけ実施。まず合成写真で行い、実写真は別途明示された範囲に限定する。
- 旧ベクトルの再計算はAPI性能によって時間が掛かる。旧結果を保持し、完了してから切り替える。クラウド再計算へ暗黙に逃がさない。
- 長いHTTPは終了を遅らせるため、要求期限・SIGTERM時の合計期限・systemdの終了待ちを同時に試験する。読み取り・管理の受付は独立させる。
- active indexの変更は、既存photos/admin/searchの読み取り経路を横断する。切替前後・モデル停止中の公開契約の回帰試験を必須にする。
