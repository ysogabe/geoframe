## 背景と目的

Rust版には取り込み・管理・画像配信があり、AI検索の実処理とAIワーカーはまだ無い。Python版ではAI処理の待ち・失敗・再試行がメモリや個別の結果表に散らばり、モデルの停止や入力更新に対応する共通基盤がない。

P4では推論を外部HTTP APIへ移し、停止しても残るジョブ、用途別の送信設定、ベクトル空間を区別した索引を作る。既存写真・人手の修正・過去に得た有償のAI結果を保ちながら進める。

## 使う人と場面

- 利用者: 写真を追加し、検索・代表写真の確認・位置の手動修正を行う。モデル停止中も写真を閲覧する。
- 管理者: モデル停止やGPUの占有による待機を把握し、復帰後の再開や失敗ジョブの再試行を行う。
- miharashi: 従来のフィードと画像を継続して読む。

## ゴールと対象外

対象はE5/E6のAI検索・状態、Embeddingと同一場面の整理、任意のGemini判定、Decision経由の位置候補、およびその実行基盤。写真フィードや既存管理画面の契約を維持する。

P5の本番切替、推論サーバーの実装や起動停止、旅行ブログの作り直し、表示クライアントの変更は対象外。古いモデル出力や順位の数値一致は求めない。既存の有償結果の一括削除や、画像Embedding API未確定のままの専用クライアント実装は行わない。

## 要求

- **R1 必須: 永続ジョブ。** 種別・対象・入力世代・処理版・送信ポリシーを区別し、完了、再試行待ち、利用不可による後回し、上限到達、古い入力による無効化を記録する。プロセス再起動で未完了の仕事を失わない。
- **R2 必須: 障害からの独立。** Provider停止、GPU lease、遅い応答中もフィード・画像・管理APIを使える。GPUの起動停止・lease取得・解放をGEOFRAMEが行わない。AIワーカーの起動には既存writerと取り込みガードを使う。
- **R3 必須: 入力の保護。** 写真の更新・回転・削除やモデル切替の後に古い応答を確定しない。AIは手動GPS・お気に入り・除外・回転を書き換えない。位置候補は人がSAVEするまで提案のまま。
- **R4 必須: 用途別の送信。** 画像Embedding、写真比較、位置候補、検索語Embeddingの送信先とクラウド許可を別々に指定する。未設定のクラウド送信は無効。用途ごとの1日送信上限と周期上限をDBで保持し、再起動後も有効にする。LAN側の停止をクラウドへの自動切替の理由にしない。検証での実写真送信には別途、その用途の許可を確認する。
- **R5 必須: ベクトル空間。** model、revision、画像／文の前処理版、次元、正規化規則、空間IDを照合する。新しい索引を別に構築し、準備中は旧結果を保持する。検索索引の変更だけでは有効な旧選別を解除しない。旧データの不足する版情報を推測で補わない。
- **R6 必須: AI検索・状態。** E5/E6のJSON形・入力・状態コードを既存画面が扱える形で維持する。空検索は保存済み推薦を使い、外部推論を要しない。意味検索は適合する検索語Embeddingが無ければ定型503、合うキャッシュがあれば利用できる。毎分30件、検索語300文字、グループ数1〜30の既存規則を維持する。
- **R7 必須: 選別・位置候補。** 同一場面は時刻と同じ空間の近傍でまとめ、ルールの代表選択を基本とする。既存`rank_model.json`は形式を検証して利用し、未配置時は固定式。Gemini比較は用途の許可がある場合だけ。位置候補はその日のDecision判定が完了し、手がかりがある画像だけ送る。
- **R8 必須: 既存データと切り戻し。** 既存の有償Embedding・判定結果を消さない。新しい索引と旧結果の互換境界を明示し、Pythonへの切り戻しを合成DBで確認する。追加表で移行し、既存列の意味を変えない。
- **R9 必須: 検証・秘匿。** テストの通信はスタブ。検証用LXCで停止・復帰と実APIを確認する。写真、座標、地名、検索語、認証情報、送受信本文をログ・fixture・PRへ出さない。結果は件数・時間・合否だけを記録する。

## 制約

- 現行の単一バイナリ・musl・`ureq`・共有`Writer`を使う。AIの通信をTokio workerやwriter上で実行しない。
- 開発機が本番機であるため、本番のサービス・設定・データを変更しない。検証は従来のLXCと専用複製で行う。
- ローカルにTorch/Transformersを持ち込まない。既存のテキスト専用`llm-embed`に画像を送らない。
- Geminiは既存のVertex系HTTP契約を基本とし、認証ファイル・プロジェクト・モデルを明示設定する。今回のDrive鍵の使用許可をクラウドAI送信の許可へ拡張しない。

## 外部依存と確認待ち

1. [local-model-lab #93](https://github.com/ysogabe/local-model-lab/issues/93)は2026-10-26の確認でOPEN、API契約や採用結果のコメントは無い。`main@2c78c9910b2931ca7d2f42e8e35a5ebaa999e814`の[サービス定義](https://github.com/ysogabe/local-model-lab/blob/2c78c9910b2931ca7d2f42e8e35a5ebaa999e814/config/llm/profiles.json)もEmbeddingはテキスト専用。画像APIの実装・性能評価は別リポジトリの作業。
2. #93でパス、JSON、画像と文の版情報、上限、CPU/GPU配置が決まったら、P4設計の接続契約を追記する。GEOFRAME側から仮の本番パスを決めない。
3. クラウド利用を有効にする際に、用途・画像送信・費用をユーザーと確認する。設計では未設定時無効を既定にするため、前半の着手条件ではない。
4. 旧Embeddingの版が確かめられなければ新索引で再計算する。再計算の方式・時間は#93の測定後に決める。既存の結果は保存する。

P5では、実APIで検証した新しい空間の索引と意味検索が準備済みであることを関門にする。旧ベクトルの版が不明だからという理由で、切替後の意味検索503を恒常状態として受け入れない。管理者が根拠を持って旧空間を宣言する経路は、モデル・重み・両前処理の版と実測照合がそろう場合にだけ設ける。単なる設定文字列による一致の宣言は認めない。
