# ADR: GeoFrame内に旅行ブログ・レビュー機能を追加する

- 日付: 2026-08-04
- 状態: 採用（MVP）

## 文脈

旅行後、既存のGeoFrame写真DBから旅程に対応する写真を抽出し、ブログの下書きと静的HTMLを作りたい。元写真を変更せず、公開前に利用者が写真・本文・事実を確認できる必要がある。

## 決定

既存のPythonサーバーへ小さな `geoframe.travel_blog` モジュールを追加する。

- 旅程は `travel_blog/plans/*.json` として管理する。
- 写真候補APIは `catalog.db` を読み取り専用で参照し、撮影日、位置情報の有無、お気に入りを使って候補を作る。
- ブログAPIには正確な緯度経度とDrive認証情報を返さない。
- 下書きは `travel_blog/drafts/*.json`、書き出しは `blog_exports/<trip_id>/` に分離する。
- 書き出すJPEGはPillowで再エンコードし、EXIFを引き継がない。
- 本文はまず決定的な事実アウトラインを作り、未確認事項を `[要確認]` として残す。外部LLMはMVPの必須依存にしない。
- 自動公開は行わない。

## 理由

既存サーバー、SQLite接続、表示用画像、Host/CSRF対策を再利用でき、新しいフレームワークや別サービスを運用する必要がない。写真索引を再構築しても、利用者が編集したブログ下書きは失われない。

## 制約と次段階

MVPの重複整理は同一分の連写グループであり、画像内容の近似判定ではない。次段階ではpHash、ブレ・露出評価、写真ごとのタイムゾーン補正履歴、任意の文章生成プロバイダを追加する。これらを追加しても、旅程→候補→レビュー→静的出力のAPI境界は維持する。
