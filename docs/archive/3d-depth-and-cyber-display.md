# 3D PHOTO JOURNEY: 奥行きとサイバー地形

ステータス: 実装・N100隔離プレビュー確認済み、本番反映済み（2026-09-10）

実装の契約と調整値の一覧は
[3D PHOTO JOURNEY Lite（Navara）の実装契約](3d-photo-journey-lite.md)にあります。

## 採用した表示

通常の3D表示は、暗い青の地形と撮影地点周辺のシアン線から開始する。
詳細な航空・衛星写真が得られた地点では、写真を約1.8秒かけて地形へ重ねる。
写真がない場所では暗い地形を維持する。ユーザーの実装指示を受け、通常3Dの
既定をこの `hybrid` 表示へ変更した。2Dの表示設定には影響しない。

| URL設定 | 表示 |
| --- | --- |
| `?mode=3d` | 通常は `hybrid`。暗い地形から詳細写真へ移行 |
| `?mode=3d&terrainStyle=cyber` | 写真なしの暗い地形とシアン線。地図写真タイルも先読みしない |
| `?mode=3d&terrainStyle=photo` | 従来の写真地図。国内は航空・衛星写真、海外はOSM |
| `?mode=3d&low` | 省電力の `cyber`。周回と写真フェードを省く |

`low&terrainStyle=hybrid` を明示しても写真を取得せず、サイバー地形を維持する。
`low&terrainStyle=photo` は従来の省電力写真表示を利用できる。

## 実機画面から確認した問題

サーバーから取得した2560×1080の実機スクリーンショットでは、背景写真の細部が
柔らかく、地形の起伏も読み取りにくかった。HUDの暗いパネルとシアンなどの色は
既にサイバー調に合っていたため、背景の地形を整える方向を採った。
実写真・座標・個人パス・実ホスト名を含む検証画像はコミットしない。

写真の粗さには、内部描画倍率0.5に加え、GSI画像のズーム帯が影響している。
Z2–13はLandsat8、Z14–18はシームレス写真で、遠景は粗い画像になりやすい。
DEMは標高の面を作るが、画像の元解像度や建物の立体形状を増やすものではない。

Navara 0.1.1の合成処理では、hillshadeと同じスロットの `raster.show=false` が
陰影まで除外していた。`show=true, opacity=0` に変更し、生のDEM色を隠しながら
斜面の陰影を有効にした。初期化時にも `useNormal=true` を渡している。

## カメラと地形

- 写真の座標を注視点とし、後方からその場所を見込む。通常は地面から1,400m、
  俯角24度。省電力も1,400mとし、俯角だけを28度にする。検証済み実標高を優先し、
  不明なら常駐DEMを参照する。
- 地形照明は地点の地方太陽時15時相当に固定。実際の現在の日照を示すものではない。
  hybrid/photoは環境光0.48・太陽光1.15、cyber/lowは環境光0.92・太陽光1.50とする。
  hillshade強調1.35。影や重いポスト処理は追加しない。
- 滞在は90秒以上。常時アニメーションは無効とし、到着後の精細化を通常400ms間隔で
  hybridは75秒、それ以外は55秒まで行う。省電力は800ms間隔・60秒まで。
- 通常は到着45秒後から8秒間、22度の短い周回で視差を見せる。省電力・動きを減らす
  設定・航空機割り込み・スリープでは周回を停止する。
- 画面に固定された格子を隠し、走査線と周辺の暗転を弱めた。

シアン線は撮影地点から400/800/1,200mの途切れたリングで、等高線ではない。
地形の取得済み標高を持つ幅8mの細い帯を `perPositionHeight` のpolygonとして描く。
地面とのちらつきを避けるため標高に12mを足し、精細化中に15秒ごと・最大6回更新する。
通常は12本・708頂点まで、省電力は半径500/1,000mの8本に減らす。
標高未取得の区間は描かない。cyber/Lowは四角いメッシュを重ねず、半径120/220/340/500/700/950mの
全周リングを中心密度高く描く（通常cyberは160/280/420/620/900/1,200m）。外周へ行くほど
間隔が広がるため、注視点の周辺だけを読みやすく強調できる。写真表示にはリングを重ねない。

カメラは未取得の周辺地形との衝突回避を保証しない。平野は実地形として平らに見える。
建物や等高線の全面生成は今回の範囲に含めない。

## 写真の適用条件と負荷

hybridではZ14以上の詳細写真を表示し、判定と先読みはZ14に絞る。Z13以下への
`/tiles/gsi-photo/{z}/{x}/{y}.png?detail=1` は透明PNGと `X-Tile-Cache: skipped` を返し、
上流取得も通常写真のファイルキャッシュへの書き込みも行わない。
クエリなしの写真表示は従来どおりZ2–18を利用できる。

Navaraソースの開始ズームは2を保つ。開始を14へ直接上げる試作では、親LODの探索が
進まず大きな面が残った。写真上限は提供範囲どおり18を保ち、hybridの `maxSse=3` で注視点の精細化を
優先する。写真上限を14に絞る比較では近景の写真が表示されず、採用しなかった。通常photo/cyber/Lowの
maxSseは4、GPUキャッシュ上限は全モード512MiBでそろえる。

写真への移行は次のすべてを満たしてから始める。

1. 通常のhybridで国内の写真対象地点にいる。
2. 到着後55秒以上が経過している。
3. 注視点を囲むZ14の3×3タイルを完全に受信し、全9枚の `X-Tile-Content` が
   `imagery` である。HTTP失敗・`error`・`throttled` は適用しない。

透明代替タイルは `empty` と判定する。RGB写真はピクセル展開を省き、alphaを持つ
PNGだけをデコードする。判定キャッシュは256件、ブラウザ側は1,024件に制限する。
判定用の取得は古いヘッダを再検証し、通信失敗や空の応答は次回訪問時に再確認する。

先読みは通常15秒後、省電力60秒後から既存の回数・同時接続上限内で行う。
判定に必要な9枚を先に取得する。高ズーム写真は画面内の描画要求に任せる。
海外のhybridは暗い地形を保ち、OSMを航空写真の代わりに適用しない。

移行は20Hz・1.8秒のsmoothstepで写真レイヤー全体をフェードする。
タイルごとの走査波エフェクトではない。動きを減らす設定では即時切り替える。
次の写真・航空機イベント・スリープ・終了で古いフェードと線更新を停止する。

**制約:** 上記はサーバーから画像を取得できたという判定であり、画面内すべての
GPUテクスチャの読み込み完了判定ではない。遠景や未取得領域には暗い地形が残る。
この実装はGPU側の全タイル完了APIを前提にしていない。

## 検証

現状確認にはサーバーから取得した実機スクリーンショットを使用した。
変更後の試作比較にはサーバーの実写真・地形タイルを読む独立したローカル
ブラウザを使用し、最終確認はN100上の空プロファイルのheadless Chromiumと
一時HTTPプレビューで行った。既存の通常表示は変更していない。
航空機割り込みは比較時に除外した。ローカルとN100の測定を区別する。

N100のIntel GPU（Mesa/ANGLE）を明示して2560×1080で撮影し、40秒時点の
暗い地形＋シアン線を確認した。Lowでは旧来の粗いLOD設定が地形メッシュを一枚も保持しない
ことが分かったため、地形品質を通常値へ戻して再計測したところ、`retainedTerrain=13`、
`gpuBytesEst` 約435MB（予算512MiB）となり、起伏とシアン線を読み取れる画面になった。
照明はcyber/Lowだけ環境光0.92・太陽光1.50へ強め、WebGL初期化エラーは発生しなかった。

最初のheadless検証はソフトウェア描画に切り替わっており、標高付きのシアン線が
見えなかった。これはGPU表示の確認に使わず、Intel GPU名を取得できた後の画像を
最終確認に使用した。検証ブラウザには空プロファイルを使い、終了後に停止した。
これらは短時間の隔離プレビューであり、常用キオスクの長時間安定性を保証する測定ではない。

Python 91件とJavaScript 7系列が成功。自動テストは写真の実画像/透明判定、低ズームの省略、通常キャッシュの保持、
GET/HEADヘッダ、フェード開始条件、中間不透明度、途中切断、一部欠損、古い応答、
スリープ・航空機割り込み・終了、低電力時の写真取得抑止を検証する。
既存のカメラ、DEM、航空機、スケジューラ、画面配置、配布バンドルのテストも実行する。

常用キオスクへの反映後には10–30分の連続描画、メモリ上限、周回完了、復帰を
追加確認する。ソフトウェア描画へ落ちた環境での線の互換性は残る制約であり、
ハードウェアGPUを使用する構成を前提とする。
