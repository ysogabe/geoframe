# 地理空間MCP ナレッジベース

作成日: 2026-07-28 / 情報源: 国土交通省公式ページ・GitHubリポジトリ（ソースコード解析含む）・不動産情報ライブラリAPIマニュアル

---

## 1. 地理空間MCPとは

国土交通省が公開した **MCP (Model Context Protocol) サーバー**。Claude DesktopなどのLLMホストから自然言語で「不動産情報ライブラリ」の地理空間データ（30種類のAPI）を呼び出せる。

- 公式ページ: https://www.mlit.go.jp/tochi_fudousan_kensetsugyo/tochi_fudousan_kensetsugyo_fr17_000001_00047.html
- リポジトリ: https://github.com/chirikuuka/mlit-geospatial-mcp （MIT License, Python 100%, ★176）
- ステータス: **α版**（動作保証なし、予告なく変更・削除の可能性あり）
- 2026-03-16 に災害系5データセット追加（洪水・高潮・津波浸水想定、土砂災害警戒区域、人口集中地区）

## 2. アーキテクチャ

```
Claude Desktop (MCPホスト)
   └─ stdio ─ src/server.py (MCPサーバー / Python 3.10+)
                └─ ツール: get_multi_api （単一ツールに30API統合）
                     ├─ ジオコーダ: 国土地理院API（住所→緯度経度、緯度経度→市区町村コード）
                     ├─ 座標変換: 緯度経度→XYZタイル座標
                     ├─ requester: 不動産情報ライブラリAPI呼び出し（APIキー必須）
                     ├─ point_filter / polygon_filter: 実距離・重なり判定でフィルタ
                     └─ map_url_generator: 不動産情報ライブラリの地図表示URL生成
```

処理フロー: 緯度経度＋距離 → 必要なXYZタイル(z,x,y)を内部計算 → 該当APIを呼び出し → 中心点からの実距離（ポイント系）またはポリゴン重なり判定でフィルタ → GeoJSON＋地図表示URLを返却。

## 3. MCPツール仕様: `get_multi_api`

**必須パラメータ**: `lat`（緯度）, `lon`（経度）, `target_apis`（API番号の配列。空配列=全API）

**主な任意パラメータ**: `distance`（検索半径、**上限425m**）, `year`（1995〜。デフォルト2024）, `quarter`, `price_classification`, `land_price_classification`, `use_category_code`, `administrative_area_code`（5桁）, `prefecture_code`, `save_file`（GeoJSON保存フラグ）, `output_dir` など

**返却**: 各APIの結果（GeoJSON）＋不動産情報ライブラリの地図表示用URL

### データ型別の挙動

- **ポイント/ライン**: distance上限425m。複数タイルを取得し実距離でフィルタ
- **ポリゴン**: 指定した緯度経度と**重なるポリゴンのみ**返却（例: 「この地点は洪水浸水想定区域内か？」に即答できる）
- **API 1（取引価格）**: 座標情報がないため地名でフィルタし、座標を付与して返却

## 4. バックエンド: 不動産情報ライブラリAPI

MCPを介さず**直接REST APIとして利用可能**（アプリ開発ではこちらが本命）。

- マニュアル: https://www.reinfolib.mlit.go.jp/help/apiManual/
- 認証: APIキーをヘッダー `Ocp-Apim-Subscription-Key` に設定（HTTPS必須）。利用申請→審査→発行
- レスポンス形式: **GeoJSON** と **PBF（バイナリベクトルタイル）** の2種
  - PBFはMapLibre GL JS等の地図ライブラリに直接食わせられる → リアルタイム地図表示に最適
- 位置系APIは **XYZタイル指定**（z/x/y）で取得
- レート制限: 明示上限なし。ただし連続大量リクエストで制限の可能性 → **タイルキャッシュ推奨**
- 利用約款の確認必須

## 5. セットアップ（MCPサーバー）

1. Python 3.10+ / Claude Desktop
2. 不動産情報ライブラリでAPI利用申請 → `LIBRARY_API_KEY` 取得
3. `git clone` → `python -m venv .venv` → `pip install -r requirements.txt`
4. `claude_desktop_config.json` に command（venvのpython）/ args（`src/server.py`）/ env（`LIBRARY_API_KEY`, `PYTHONUNBUFFERED=1`, `LOG_LEVEL=WARNING`）を設定

## 6. アプリ開発視点の要点（設計判断メモ）

- **MCP＝対話用、REST API＝アプリ組み込み用**。常時表示アプリ（スマートディスプレイ等）はMCP経由ではなくREST API直叩き＋PBFタイルが正攻法。MCPは「自然言語で分析する」体験のレイヤに使う
- ポリゴン系APIは「地点判定」に強い（防災・用途地域）→ 位置ベースのコンテキスト表示に好適
- ポイント系は425m制限あり → 広域表示にはタイル単位取得を自前実装するかPBFタイルを使う
- 地理院ジオコーダ（住所⇔座標）は無認証で使える汎用部品
- APIキーはクライアント（ブラウザ）に直接埋め込まない → プロキシサーバー経由が必須（マニュアルにも明記）

## 7. GeoFrame実装との対応

本ナレッジ（§1〜4）で説明した不動産情報ライブラリAPI・タイル方式が、GeoFrame本体 `app/geoframe/mlit.py` で実際にどう使われているかの対応表。

### 7.1 地点詳細（AREA INTEL）

写真の撮影地点1件ごとに `api_intel` 関数（`app/geoframe/mlit.py`）が以下4種のAPIをその場で呼び出し、HUDに表示する。

| API | 名称 | zoom / タイル | 使用プロパティ |
|---|---|---|---|
| XKT002 | 用途地域 | z13 | `use_area_ja`（用途地域名）、`u_floor_area_ratio_ja`/`u_building_coverage_ratio_ja`（容積率/建蔽率） |
| XKT026 | 洪水浸水想定 | z14 | `A31a_205`（浸水深ランク）、`A31a_202`（河川名） |
| XKT013 | 将来推計人口2050 | z13 | `PT00_2050` |
| XPT002 | 地価公示ポイント | z15・2×2タイル・`year`必須 | 当年→前年の順で試行し最寄りポイントを採用 |

浸水深ランク（`A31a_205`、1〜6の数値）は以下の6段階表示に変換される: 1=0.5m未満, 2=0.5〜3m, 3=3〜5m, 4=5〜10m, 5=10〜20m, 6=20m以上。

### 7.2 地震監視（SEISMIC WATCH）

`HAZARD_APIS` 定数（`app/geoframe/mlit.py`）で定義される6種のAPIを、地震発生時に震央周辺でまとめて取得・表示する。

| API | 名称 | zoom | タイルグリッド |
|---|---|---|---|
| XKT025 | 液状化発生傾向 | z11 | 2×2 |
| XKT029 | 土砂災害警戒区域 | z11 | 2×2 |
| XKT022 | 急傾斜地崩壊危険 | z11 | 2×2 |
| XKT021 | 地すべり防止地区 | z11 | 2×2 |
| XKT028 | 津波浸水想定 | z14 | 4×4 |
| XKT026 | 洪水浸水想定 | z14 | 4×4 |

注記: 洪水（XKT026）・津波（XKT028）はz14以上でないとデータが提供されない（z11では0件、2026-07-29実測とコードにコメントあり）。そのため他4種とzoomレベル・タイルグリッド幅を分けている。

### 7.3 タイルキャッシュとレート制限の実装

- **ファイル永続キャッシュ**: `hazard_tile` 関数（`app/geoframe/mlit.py`）が取得したタイルを `{XKTコード}_{z}_{x}_{y}[_extraのサフィックス].json` というファイル名で `GEOFRAME_DATA_DIR/hazard_cache/` に保存し、次回以降はファイルから読む（キャッシュヒット時はAPIを叩かない）
- **point-in-polygon自前実装**: `_pip` 関数（`app/geoframe/mlit.py`）がレイキャスティング法で実装。ポリゴンの外環（outer ring）のみを判定対象とし、MultiPolygonにも対応
- **APIリクエスト間隔**: `hazard_tile` 関数内で新規取得時のみ `time.sleep(0.15)`（150ミリ秒、`app/geoframe/mlit.py`）を挟む。キャッシュヒット時はスキップされる。不動産情報ライブラリの運用ポリシーへの配慮とコードにコメントあり

### 7.4 気象庁データ（無認証・地震速報とは別枠）

気象庁の予報・地震情報（`JMA_FORECAST`/`JMA_QUAKES`、`app/geoframe/config.py` と `app/geoframe/jma.py`）も実装済み。`GEOFRAME_JMA_AREA` 環境変数で予報区コードを指定できる（既定値は120000=千葉県）。この節は不動産情報ライブラリAPIとは別の無認証データソースであり、本ドキュメントの主題（地理空間MCP・不動産情報ライブラリ）の守備範囲外だが、実装済みであることをここに書き添える。
